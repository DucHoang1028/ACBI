# Phase 4 verification — 20 September 2026

Phase 4 adds saved answers and conversation history, an editable voice transcript flow, local user administration, deterministic summaries, controlled storage-failure responses, and a five-request concurrency check. The app stores question, answer, rows, validated visualization, executed SQL and bound parameters, retrieval time, metric version, source references and original data anchor in its internal PostgreSQL database. The warehouse remains external and read-only. Each history or saved-result read checks current ownership, role and Factory A scope again. Role changes revoke active sessions.

The [Phase 4 verification record](phase4-verification.json) uses FakeLLM and FakeSTT against the running containers. It checks reopen and cross-user denial, no-data persistence, partial response when saving fails, voice transcript review and empty-transcript failure, administrator boundaries and user management, five concurrent requests, and controlled AI/DB failure responses. The five in-process requests had a measured p95 below 15 seconds; this is a local backend measurement, not a claim about Internet or live-model latency. The [40-question structured-intent run](phase2-verification.json) and [six-question generated-query run](phase3-verification.json) also pass after Phase 4 persistence changes. Across their independently reconciled `ok` cases, 34/34 answerable FakeLLM questions passed; four `no_data` cases returned no fabricated rows. Clarifications and denials were excluded from the answerable score. Simulated timeout/failure checks do not prove provider availability under load.

The owner approved sending the [documented business context](PHASE_3_EXTERNAL_CONTEXT.md) to Groq. The local setting `EXTERNAL_METADATA_ENABLED=true` is active. A live Groq weekly-revenue question succeeded through RAG SQL validation with five warehouse rows, a line chart, three model calls and a saved result. This one smoke test does not establish a 90% live-model accuracy rate. Live voice transcription cannot be assessed without a user audio sample; FakeSTT covers the review flow. Groq's multilingual `whisper-large-v3-turbo` transcription endpoint is the default, with audio sent only when the user selects **Stop and transcribe**. The [Groq speech-to-text documentation](https://console.groq.com/docs/speech-to-text) describes its supported endpoint and formats.

`SEND_RESULTS_TO_LLM=false` remains the default. Factual summaries are built from executed rows and resolved dates. An optional model-summary path and numeric guard exist, but sending result rows needs separate `EXTERNAL_RESULTS_ENABLED=true`; that setting remains false because the owner's Groq approval covered metadata, not result values. Failed or numerically inconsistent model summaries fall back to the factual text.

Docker Compose still runs exactly three ACBI services and no AdventureWorks service. The existing external warehouse folder was not modified or copied. Production exposure still needs HTTPS, verified warehouse TLS, and a deployment review. This run is a local prototype evaluation.
